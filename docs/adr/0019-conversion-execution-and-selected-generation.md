# 0019 转换执行的只读校验、安全发布与选中范围生成

转换执行前的库存刷新重走 staging／merge，提交又重复探测和读取完整散列；生成则串行刷新每个成员。这些成本与编码池无关。执行改用只读观察校验和执行期对象事实，生成在实测门槛通过后采用选中范围批扫。rename、metadata 和完整入库扫描继续原流程；计划格式、HTTP/SSE 载荷、数据库 schema 不变。

## 1 执行范围与任务会话

本决定窄范围替代 [ADR 0001 §2](0001-library-workbench-and-processing-record.md) 的 conversion 执行刷新方式。StartExecution 与 worker 都以实际冻结执行单元的根判断输入；详情仍判断整份计划，全局阻塞、版本、草稿、幂等和每计划一次执行继续有效。没有操作的选中根不增加执行单元；空执行不扫描。

conversion 的可选 ExecutionSessionFactory 接收冻结单元、outcomes 和选项，在首个编码前固定工具配置并返回会话级 UnitPreparer。其他任务保留原校验流程。读盘使用默认／上限 32 的 scan.workers，作品内部顺序遍历，复用路径规范化和 Delete 排除。音频指纹仍是路径、size、整数 Unix 秒 mtime；数量和指纹匹配时不创建扫描 session，不写 staging、不 merge、不回读音频库存，也不刷新非音频库存。

缺失或不匹配先尝试原串行刷新，仍报 INPUT_CHANGED；刷新错误附诊断。初始权限／I/O 错误为 SCAN_FAILED，原始取消为 CANCELED。已确认输入改变后，刷新期间的取消不掩盖 INPUT_CHANGED。

## 2 句柄与组件提交

本决定窄范围替代 [ADR 0007 §1、§3、§6](0007-execution-sessions-and-component-results.md) 的重新探测与发布原语；编码池、组件窗口和串行准备／提交／逐组件持久化保持原决定。

需要编码时会话检查工具、读取版本各一次，每种实际输出容器通过短 PCM WAV 的 FD 编码、探测及完整解码 roundtrip。纯删除及空执行不依赖工具。路径预检、逐级符号链接检查和 withinRoot 保留；路径预检和源句柄核对共用纯事实比较，保留未指定字段及冻结 mtime ±1 秒容差。每个 worker 拥有独立源／输出句柄，顺序调用前复位游标；源对象改变归入 materialize。FD 不阻止外部原地修改内容。

编码 worker 先做一次源探测（WAV 同时读取原始标签，修复仍是 best-effort）再编码，Encode 返回源流事实。worker 检查写句柄的 Sync 和 Close，再通过根内只读句柄核对同一对象和大小。ValidateOutput 接收源事实与只读输出句柄，返回已验证流事实及所需 SHA-256；输出探测、所需完整解码及散列全部在关闭写句柄后完成。Linux 与 Windows 使用同一生命周期，不引入 CloseStage 端口、文件系统类型分支或 SMB 专用锁。

暂存输出由单个任务独占，随机名称及 O_EXCL 防止共用，编码返回后再校验，组件提交等待其全部编码任务结束；服务内直接文件管理与执行互斥。正常业务不会并发改写该暂存物，执行只保留身份、普通文件和大小核对，以及清理时的文件归属保护。暂存输出 mtime 仅作为观察到的库存／凭据事实，不在校验期间或发布前要求相等，也不为其等待稳定。SMB 延迟更新 mtime 不再导致失败；同一对象内保持大小的外部改写不属于本流程承诺检测的风险。源文件冻结校验及替换／删除旧文件前的复核仍保留。

输出探测仍校验 codec、channel、sample rate 与源时长 ±0.1 秒，不加 count_packets。-v error 的探测／解码必须退出成功且 stderr 无非空白内容；取消先于 stderr 归类。编码成功后，输出探测、完整性／解码／散列或对象核对失败报 COMPONENT_VALIDATE_FAILED，stage 仍是 materialize；编码本身失败继续 COMPONENT_ENCODE_FAILED。前端已有 error_message／error_code 回退，无需修改。

当前组件自己的全部声明任务投递、返回成功后，首次发布前整遍检查该组件暂存对象，失败为 validate，没有输出发布。每次发布前再次检查对应暂存对象，替换或删除前检查旧对象；后续失败为 commit 或 remove，保留已发布结果。两层暂存物核对只比较身份和大小；发布前利用已有查询记录最新观察到的 mtime，不额外 stat 或重新散列。仅实际已发布输出使用捕获事实和散列生成凭据，提交后不完整 hash／重复 stat。

协调者在同一个 select 中等待头组件完成、投递当前待送任务或取消；没有待送任务时将发送 channel 置 nil。每轮优先检查已就绪头组件，后续多任务组件的有界队列背压不能拖住它的提交和持久化。PrepareUnit 仍串行、投递仍 FIFO、窗口仍 W=N。部分投递的拆除只结束该单元投递；既有 delivered==expected 规则阻止误提交。池／窗口启动时读取 execute.max_io_workers，1–32 显式生效，缺失、无效、非正和越界为自动 min(4, CPU count)，默认 0；工具配置仍每会话固定。


FD 格式验收保留所有现有输出格式、标签与 seek；末尾 moov 的普通 AAC M4A 验证同一 FD 输入探测／完整解码方法的 seeking，不改变规划对无损编码源的选择规则。Linux 打开后改名仍读原对象；Windows 当前共享模式禁止打开期间改名，关闭后可以删除。

## 3 严格移动与预探测

conversion 使用独立移动能力，通用 RenameNoReplace 不变。Linux 优先 RENAME_NOREPLACE，原语不支持时普通文件可同挂载硬链接目标再 unlink 源。statx 的 STATX_MNT_ID 不可用时解析 mountinfo，保留转义及路径边界；不能确认挂载身份就失败，不退回 st_dev。相同设备上的 bind mount 仍属跨挂载。Windows 使用原生无覆盖移动并按卷身份与挂载边界比较；其他平台明确 unsupported。

NFS 的 link EEXIST 可能是成功请求的重试：源、目标都与调用前捕获的源身份相同才认为成功；不同文件为冲突，无法确认则为未核实。返回目标创建、源名移除和未核实事实。链接成功而 unlink 失败保留目标并报告部分发布；未核实结果保护可能的唯一副本，不让 cleanupTemps 删除其名称，并披露库存未核实。替换保护、恢复和反向恢复都用同一接口；竞争者占用恢复目标时保留旧文件。

输入校验通过后、编码前，对实际移动需求先验证每个源／目标挂载对，再按挂载 ID 去重，选择实际目录对进行拒绝覆盖和成功移动探测。soft 且存在删除／替换时才探测 recovery，使用最深已存在恢复祖先，不创建空 Delete 目录；hard 不探测 recovery。scratch 独立跟踪，名称含 .tmp.<唯一标识>，失败或取消清理并披露残留；命名不提供自动扫描排除或跨进程清理保证。

不支持报 FILESYSTEM_OPERATION_UNSUPPORTED，权限／I/O／探测清理失败报 FILESYSTEM_PRECHECK_FAILED。文案仅称“未开始转换”。工作根本身为挂载点时，同级 Delete 位于另一挂载，过去 rename 就可能 EXDEV；现在提前发现这一既有限制，包括同设备号的 bind mount，不属于新的恢复布局回归。真实操作仍处理探测后的运行时失败。

依据：[statx mount ID](https://man7.org/linux/man-pages/man2/statx.2.html)、[NFS link 重试](https://man7.org/linux/man-pages/man2/open.2.html)。

## 4 生成批扫的采用依据

测量使用同一真实 NAS 选中范围（39 个作品目录）、相同工具配置和同一静止 SQLite 备份的独立副本，每次启动实际生成会话并要求 Created=true、没有可复用 revision。媒体与原库只读。手动验收入口为 TestMeasureConversionGeneration；通过 CONVERSION_MEASURE_DB、CONVERSION_MEASURE_WORKSET、CONVERSION_MEASURE_OUTPUT 选择备份与结果，CONVERSION_MEASURE_CANDIDATE 交替基线／候选。不新增 CI 性能门禁。

计时分别记录总 T、纯遍历和每目录耗时、staging S、merge M、回调背压；纯 walk 减去 emit 等待，数据库活动不重复记入 walk。n=min(32,目录数)，Gwalk=max(0,W-max(W/n,Wmax))；没有隔离数据库节省证据，Gdb=0，Gest=min(T,Gwalk+Gdb)。事先门槛为五次 Gest/T 中位数至少 20%，再试做；交付要求交替五组的总耗时中位数至少降低 5% 且至少四组改善。

## 5 输出校验的风险边界与 Opus 采用门槛

MP3 和 M4A 保留关闭写句柄、只读重新打开、对象事实核对、输出探测、完整解码及有损输出 SHA。探测比较 codec、channels、sample rate 和源时长 ±0.1 秒；探测／解码使用 -v error，非零退出或非空白 stderr 均失败，取消优先。正常 adapter 输出的格式矩阵（包括 MP3 的 8–48 kHz、mono/stereo、大标签及 M4A 章节 track）验证这条 stderr 规则不会拒绝正常输出。不增加 MP3 Info／长度／标签 CRC／music CRC 解析，也不增加 M4A Box 闭合及 stco/co64 遍历；对应解析器故障矩阵撤回。

完整解码和 ffprobe 时长不是文件完整性证明。固定 FFmpeg 9.0.1 的故障实验中，MP3 在帧边界截断可以完整解码退出 0 且 stderr 为空；另一些截断虽打印 invalid new backstep -1，仍退出 0，新增 stderr 规则仅覆盖后者。ffprobe 可以继续从 Info 头返回原声明时长，不能据此证明音频数据未截断。M4A 末尾截去 8 字节的实验也可以探测及解码成功。不得把移除解析器解释为解码或时长比较已经覆盖这些情况。

这里校验的是本会话自行编码的暂存输出。进程被杀或转换失败由工具执行错误／非零退出阻止发布；被报告的写入错误由工具错误及后端检查 writer.Sync()、writer.Close() 处理。写句柄到重新打开、校验和发布前保留对象身份与大小核对。mtime 记录观察值，SMB 关闭或属性缓存导致的时间更新不作为输出改变的证据。外部对同一对象的等大小修改不承诺检测，不为此稳定时间戳或增加重新读取。

接受的剩余风险是存储报告成功却静默丢失或改变数据，以及保持对象身份和大小的外部修改。MP3 帧边界截断和仍可解码的 payload 翻转可能漏检；不为这些风险扩展 MP3／M4A 格式解析器。SHA256 记录观察到的字节，缺少独立可信的预期 hash 时不能证明字节正确。这是风险与维护成本的取舍，不是通用 MP3 兼容性限制：固定 muxer 的新输出有 Info Bytes 字段且默认不写 ID3v1，不能用其他 MP3 的可选字段或历史尾部布局作为移除理由。

Opus 的候选是 Go 单 logical-stream Ogg 检查：逐页 CRC32、BOS、serial、顺序、continuation、完整 packet 与最终 EOS，EOS 后任何额外字节（包括完整有效页）明确拒绝。在同一遍读取计算 SHA；保留输出 ffprobe，省去逐文件完整解码。短 WAV 的会话 FD 能力探测仍做一次完整解码。

预先门槛为五组交替真实执行：中位总时长降低至少 5%，至少四组改善。测试用 test2 的真实 320 秒 WAV，复制为临时目录中两根、四组件，各轮独立同初始 SQLite、固定 FFmpeg 9.0.1、Opus 128 kbps 和 4 workers。计时从 StartExecution 到终态，包含只读 walk、会话探测、编码、校验、发布及逐组件库存／结果持久化；准备复制和编译不计时。基线和候选仅差 Opus 完整解码+SHA 与页 CRC+SHA 分支，临时 test overlay 计时，无生产观测接口。NAS 原媒体与运行中数据库未修改；这是临时本地发布结果，不代表 NAS 写入收益。

## 拒绝的替代方案

- 并发调用原 scanFolder：会产生多个 writer／merge，重现 SQLite 写竞争；选择并发 walk、单 writer 和一次事务。
- 无条件批扫或仅测 staging＋merge 比例：遗漏主要可并行 walk 成本，无法证明承担范围清理风险值得。
- 执行时重入扫描 session 或顺带刷新非音频：校验只需音频冻结事实，完整观察合并属于生成／扫描的职责。
- 会话级编码完成 barrier：破坏组件窗口和已就绪组件的及时提交。
- 检查目标不存在再普通 rename、仅比 st_dev、仅比链接数：不能保证拒绝覆盖或正确识别 bind mount／NFS 重试身份。
- FD 阻止所有修改、失败回滚整会话、探测保证后续成功：这些保证不成立，保留两层检查和部分结果披露。

- MP3 Info／长度／标签及音频 CRC 解析、M4A Box／stco/co64 解析：会补上一些解码漏检，但扩大了维护和误拒绝成本；本会话已检查进程、关闭和对象事实，剩余静默存储故障风险明确接受，不额外增加格式解析器。
- 所有格式共享 count_packets：增加一次全文件 demux，抵消 Opus 收益；不为已接受的静默存储故障增加读盘。
- 无门槛移除所有格式的解码：本轮仅 Opus 有完整页 CRC 和端到端采用证据。

- 暂存输出完整 mtime 防改写校验及 SMB 关闭锁：真实 CIFS 组件重放（14 任务、6 workers）中身份与大小不变而 mtime 更新；仅 Sync 或强制属性刷新均不能避免误拒绝，POSIX 锁能改善关闭时序，但引入文件系统分支与额外端口。当前业务独占暂存文件，不承担外部等大小改写的检测保证，删除时间戳门禁及其锁适配，保留 Sync／Close、身份／大小和文件归属检查。
