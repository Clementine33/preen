# 0014 元数据刷新、作品目录主封面与目录重命名规划

## 1. 抓取沿用来源数据组

沿用 [ADR 0011](0011-work-catalog.md) 的作品身份和四个完整来源数据组。
`metadata` 只接收明确指定的现有作品，含关系占位作品；`scraper` 使用固定
DLsite 与 ASMR.one API。静态、动态渠道独立读取，备用来源只补缺失的组。
销售只来自 DLsite，来源优先级和时间戳仍由作品导入判断，个人数据和副本不受影响。

Core 保留 DLsite 的三档 `age_category`（1 全年龄、2 R15、3 R18），兼容 `nsfw`
只表示是否 R18。年龄未知留空，界面不展示 UNKNOWN；年龄筛选按三档精确查询。
旧库只能从 `nsfw=true` 回填 R18，非 R18 必须刷新确认，不能推断为全年龄。

公共 `locale` 的语义是**标签语言**，UI 显示同名。简中与繁中标题分别从该编号的
`zh-cn`、`zh-tw` 响应获取，日语原作取 `ja-jp`；额外语言响应只提供标签。
中文页面与具体译作的社团严格取日语原作 `ja-jp` 响应中的编号和名称，其他基础
字段仍来自自身版本。已有来源标签与社团的显示名随已接受的 Core 更新，身份不变。

只沿来源自述的 `parent_workno`、`original_workno` 向上补抓。上游通过关系导入
建立占位身份，保存自身基础信息、关系和版本列表；不额外保存其销量或建立封面需求。
翻译关系与版本列表只保留简中、繁中，原作独立保留为根节点。父页面声明的兄弟
译作只建占位条目，不抓其元数据，也不沿版本列表扩展。单次刷新共享同编号、
来源和语言的响应，上游导入去重。原作社团或对应语言标题不可用时不提交受影响
作品的整个 Core，保留旧值；其余完整组照常提交，备用来源遵循同样规则。

详情同时显示原作、中文父页面、当前作品三节点，未知节点留空而不推断。完整
作品号查询可命中该号及其中文译作；译作须在当前媒体库范围有实际副本。按回车
时精确在库编号优先，否则唯一在库译作跳转、多个留在列表供选择。查询不联网。
缺失报告、损坏报告与明确空集合必须区分；单组损坏不得使其他完整组失效。

动态批次不超过 500，静态并发不超过 8。共享客户端有来源限速、超时、重试上限
和 403/429 冷却；取消后停止发出新请求与导入新结果。元数据执行由 workset 独立 Task 发起，不绑定目录扫描或启动事件。网页入口在媒体库工作台：概览的选择栏为所选文件夹建立“重命名”“获取元数据”记录，侧栏与“转换”并列各有一页，承载公共设置、生成计划、冻结提案评审，以及元数据的执行与封面进度。
逐作品通知发生在导入提交后；数据库错误或取消停止后续工作，单作品渠道失败记录后继续。

## 2. 重命名 Task 只生成提案

沿用 [ADR 0004](0004-task-seam-and-opaque-payloads.md) 的不透明 Task 接缝。
`rename` 拥有草稿、命名、冻结载荷与输入健康判断；workset 不解释名称。Task 的
`RequiresAudio` 控制准入：转换仍需要音频，重命名接受已扫描的作品根（可嵌套）。
公共模板设置沿用 [ADR 0010](0010-deployment-wide-common-settings.md)。

每个参与目录使用同一有限模板，没有成员命名覆盖。模板必须保留一个作品号占位符，
清理后的名称仍唯一指向原绑定作品。规划显式接收工作集保存的仓库根，仅改 basename；现有占用、批内同名冲突及新鲜度按各作品实际父目录判断，不同父目录允许同名。缺失元数据、目标占用、提案同名、保留名称和过长
名称都阻塞；Windows 大小写改名也阻塞。每成员冻结一份提案，展示原始与清理后名称。
不截断、不自动加后缀、不写磁盘。

直接使用工作集已经选定的作品路径，不重新发现作品根，不进入作品子树，不创建扫描
session、staging 或 merge。只读取各作品父目录的单层条目，同一父目录按路径去重。
新鲜度重建命名提案并与冻结提案比较，只涉及绑定、模板使用的命名字段、源目录存在／
名称／类型和目标占用。目录 mtime、媒体内容、销售、个人数据、抓取时间和未使用字段
不触发失效。既有计划同样按冻结提案判断，不再使用含目录 mtime 的旧指纹作为门禁。
评审展示冻结载荷，实时事实只决定其有效性。
执行冻结和单元准备明确拒绝 `RENAME_EXECUTION_NOT_IMPLEMENTED`，不产生执行记录。

## 3. 元数据 Task 与封面需求分开结束

`metadata_refresh` 不要求音频。草稿冻结模式、语言、下载封面选项及目录排除。
规划显式接收工作集保存的仓库根，直接使用已选作品路径，支持分处不同分类目录的作品。
只读取绑定并检查目录，不扫描分类目录或作品内容；同作品的元数据按 RJ 去重，各副本
冻结自己的 RJ、路径与设置。无绑定目录冻结为跳过提案，缺失或非目录仍产生阻塞提案。
新计划的兼容 `identity` 字段写空字符串，已有计划里的物理身份也不再作为门禁。

生成由 `GenerationInputRefresher` 跳过通用扫描；执行由 `ExecutionSessionFactory`
替代通用库存刷新和指纹复核。StartExecution 与 worker 共用一次 Lstat 的目录规则：
冻结路径必须是实际目录，返回名称必须与冻结 basename 一致。不比较 inode、大小、
mtime、当前绑定或媒体内容；同一路径和名称的物理目录替换允许执行。完整执行检查
全部执行单元，选中执行仅检查实际范围，空执行不访问目录。仍保留全局阻塞、版本、
幂等、准入和每计划执行一次规则。缺失／名称不符为 INPUT_CHANGED；权限或 I/O
错误保留诊断，worker 报 SCAN_FAILED；取消优先为 CANCELED。不增加稳定性等待、
重试或扫描回退。检查后按冻结 RJ 执行批量刷新，不重新选择目标，执行后不复核目录
或库存。绑定、目录 mtime 和作品内容变化不使新旧计划失效。
批量执行通过 workset 注册的执行接缝连接 `metadata` 与 `covers`，通用 workset
不解释两者载荷。复用版本、幂等键、执行结果、SSE 和重启中断规则。

通用计划复用仅限尚未执行且输入未变化的当前计划；已执行的计划无论终态如何，
使用新幂等键重新生成都会创建新计划，设置和目录无需改变。同键重试仍返回原生成
会话。这样保持每份计划最多执行一次，同时允许对同一批目录再次刷新元数据。

元数据导入后持久化封面需求及逐作品结果，会话即可结束。下载错误独立报告，
不改写元数据执行终态；取消元数据执行也不撤销已经排队的封面需求。
批量执行停止投递后登记本次实际执行路径，包括冻结的跳过提案。会话进入终态且本次
封面需求全部成功、跳过、失败或取消后，由封面 worker 独立触发一次选中范围库存刷新。
以需求而非共享下载状态判断结束，不等待其他执行仍需要的下载。未请求封面也刷新，
空执行不登记。沿用 scan.workers 的有限并发作品遍历、单一 staging writer 和一次
选中范围 merge，保留未选库存和绑定；准入繁忙时延后，扫描失败独立记录，不改写
metadata 或封面结果，也不自动重试。该刷新属于进程内收尾，重启不恢复待执行的刷新；
持久封面队列的重启恢复不变。显式封面重试沿用逐封面的增量同步，不再触发收尾扫描。
`refresh_dynamic` 不处理封面。只提取 DLsite `image_main.url`，失败时取 ASMR.one
`mainCoverUrl`；已抓取的响应直接提供独立候选，即使 Core 组损坏也可使用主图。
图片回退不替换整组 Core。旧 URL 字段保留兼容：`image_thum.url` 是 sample，
由 `image_main.resize_url` 推导的旧字段才是 thumbnail；新流程都不下载它们。

## 4. 单封面发布与持久队列

`covers` 拥有需求、共享下载与逐副本状态，SQLite 保存候选版本、暂存路径、结果和
条件请求记录。同作品同候选版本共享一次下载，副本结果和取消独立。
两个 worker 下载到数据目录暂存区；所有关联需求结束后删除暂存文件，启动时清理
未引用暂存文件。运行项启动后重新排队，完整暂存文件可复用，用户停止项不自动复活。
新的来源版本取消旧待处理需求；来源变更与发布串行，旧版本不能在新版本生效后落盘。

下载使用独立 HTTP 客户端，不携带 Cookie 或 Bearer token。仅允许 HTTPS 的
`img.dlsite.jp`，每次重定向及 DNS 连接地址重新检查，拒绝内网和保留地址；禁用环境
代理。每次请求超时 10 秒、上限 16 MiB，有限重试及 429/Retry-After 退避。
按实际内容和解码结果识别 WebP、JPEG、PNG、GIF，拒绝非图片、损坏文件及过大尺寸。
WebP 仅增加解码校验，不引入图片编码器；所有落盘字节保持来源格式。
只有本地文件仍在且名称、摘要、来源都匹配记录时，主动刷新才发送条件验证头并复用 304。

网络下载不持有文件操作准入。投递使用冻结目标，不重新选择或比较当前绑定及物理身份。
发布获取现有全局准入，确认冻结目录存在且名称吻合，保留路径包含关系、逐级符号链接
限制及候选版本规则；不创建缺失目录。读取封面的 HTTP 接口仍检查当前副本归属。
文件访问限定在已打开的
目录根内，拒绝符号链接。补缺时一个有效 `cover.*` 跳过，多个有效文件报告冲突，
损坏文件允许补写；刷新可替换。新文件先写目录内临时文件，检查 Sync、Close 后发布 `cover.{ext}`，
成功后仅清理顶层、确切命名 cover 且为支持扩展名的旧文件。发布记录保存新文件摘要
和旧文件名。正常发布直接复用下载字节的摘要，不复读新图片或重新计算摘要；中断恢复
仍读取新封面并确认 journal 摘要，确认落地后才调用同一旧扩展名清理逻辑。

Publication 返回已有读／写句柄阶段观察的文件事实和实际删除路径，mtime 只用于
库存记录。装配层通过 SyncObservedInventory 只更新当前封面及已删除旧封面行；
不刷新整个作品，不创建扫描 session，不触碰音频库存、绑定或未变化媒体事实。
部分清理失败也返回实际落盘事实。库存失败保留 published、报 INVENTORY_REFRESH_FAILED，
不回滚新封面，不改变 metadata 执行终态。journal 保留到增量库存同步成功，再由
CompletePublication 清理；重试用同一 journal 补齐此前删除路径的库存记录。
更新候选时将未确认的删除记录带入新 journal，并在写完整后替换旧 journal。

数据库仍采用 [ADR 0013](0013-development-schema-and-release-migrations.md) 选择的开发与发布两种生命周期，本决策不改变该边界。
接口见 [API reference](../api.md)。

转换规划同样以作品根为单位，每会话最多同时处理 4 个作品，结果保持请求顺序。
扫描、规划与编码的并发分别控制，不因可选成员变细而启动数百个规划任务。

## 5. 被拒绝的方案

- 把抓取绑进扫描：会给目录扫描增加网络依赖和未确认的自动抓取范围。
- 永久中央封面缓存、三个尺寸下载或本地转码：实测三个尺寸是同画等比缩放，目录主图已满足需求。
- 任意 URL、自动扩展 CDN 允许列表：使下载服务成为未知目标代理。
- 下载期间持有目录准入：网络等待会阻塞扫描及其他文件操作。
- 把封面错误写回元数据执行终态：异步发布有独立生命周期，元数据结果已经提交。
- 借用上级作品整组元数据或猜测父号：标题、日期与封面属于当前版本；只按确认的原作关系取得原作社团。
- 抓全翻译家族或按首个译作自动选版：兄弟译作与未收藏版本不属于本次补抓，多个在库版本由用户选择。
- 每成员模板、任意表达式和自动重名后缀：扩大语义并隐藏需要评审的冲突。
- 现在实现落盘改名：绑定、导航身份和失败恢复的写入协议需要另行明确。
- 目录级 Task 深扫描、逐封面整作品刷新或同步执行后复核：让网络刷新等待磁盘遍历和库存合并。用户要求的集中库存刷新放在本次执行及其封面队列结束之后，独立于执行门禁与结果。
- 以当前绑定、inode 或目录 mtime 拒绝元数据及封面目标：计划已经冻结 RJ 与路径，子文件变化不改变本次请求。
- 正常发布复读新图片和摘要：下载字节已经验证，写入错误由 Sync／Close 报告；仅中断恢复需要确认 journal 所描述的新封面。

## 6. 轻量流程测量

2026-10-05，以 test2 NAS 同一五个选中作品、同一初始库存的独立临时 SQLite 副本，
各生成五次，排除计划复用；只读原媒体。rename 计划中位数为 92.928 ms → 3.837 ms，
metadata 为 55.960 ms → 3.822 ms。结果包含异步会话调度及持久化耗时，是当前缓存
条件的小范围测量，不作冷扫描或整库提速承诺。转换、完整入库扫描和手动成员刷新保持原流程。
