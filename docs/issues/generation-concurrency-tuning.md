# 计划生成与内部并发调优

整理日期：2026-10-17。状态：已完成首轮 SMB 自然 / 热缓存测量并落地扫描错峰，冷缓存与独立多设备待验证。

本轮结果见[测量与首轮调优](generation-concurrency-measurement.md)。保留原会话与内部宽度默认值，转换输入刷新跨会话共享扫描槽，并优化选中范围合并、修复新连接读阻塞；不将“保留默认 2”解释为已证实最优。

## 目标与边界

单独验证计划生成并发和任务内部并发的组合，确定默认值及资源边界，再决定是否向用户开放修改。不能把“已有配置键”或某层 worker 数当作性能收益依据。

已确认优先级：机械盘 / SMB 上单个计划的响应与资源稳定优先，多计划总吞吐次之。不得仅凭总吞吐提高接受单计划明显变慢；指标冲突时应同时报告收益与代价，再决定取舍。

已确认范围：以转换计划生成为主路径，覆盖计划会话、扫描、作品分析和文件补测，同时验证轻量重命名、元数据计划的排队影响以及后台媒体事实探测的抢占。编码执行另行调优，本议题保留其现有参数和安全边界。

## 当前并发层级

| 层级 | 当前宽度 | 作用与叠加关系 |
| --- | --- | --- |
| 计划会话 | 默认 2，可配置 | 允许同时运行多个完整生成请求；不能加速单个请求 |
| 转换前库存刷新 | 每次 walk 默认 32，可配置 | 作品级遍历，随后 staging / merge；多个会话可能叠加扫描压力 |
| 单个转换计划的作品分析 | 固定 4 | 库存读取、补测与协调计算 |
| 单个作品的缺失码率补测 | 固定最多 4 | 只探测未知码率；调用媒体探测，必要时回退 ffprobe |
| 后台媒体事实探测 | 默认 8 | 独立池，可被用户任务抢占；不能直接套用为前台补测的限额 |

在补测阶段，默认组合理论上可能达到 `2 × 4 × 4 = 32` 个探测调用。扫描与分析是前后阶段，不能把 32 个扫描 worker 再乘进这个数；不同会话处于不同阶段时仍可能同时争用磁盘。

默认会话数 2 在提交 `4849654` 引入，现有记录没有 1 / 2 / 4 会话对比。历史证据见 [性能记录](adr-performance-evidence.md)，机械盘 SMB 的后台探测测量不能证明上述组合最优。

## 建议验证顺序

1. **先分段定位**：记录排队、目录遍历、staging、merge、库存读取、缺失码率探测、协调计算、快照装配及持久化。记录耗时与等待，不能将并发任务耗时求和后冒充端到端时间。
2. **先调单会话**：会话数固定 1，比较作品分析和文件探测宽度 1 / 2 / 4；先找到单会话瓶颈，再围绕有效组合缩小实验，不一次穷举所有参数。
3. **再调多会话**：在候选内部宽度下比较会话数 1 / 2 / 4。测试一个大计划、两个大计划，以及大计划加轻量计划；区分执行耗时和等待队列耗时。
4. **验证资源上限**：观察实际活跃探测数、ffprobe 进程数、CPU、内存、磁盘吞吐与等待、数据库事务耗时及 BUSY / 重试。检查用户任务抢占后台探测时是否仍有资源叠加。
5. **最后选机制**：若测量表明嵌套池放大导致吞吐停滞或延迟恶化，再比较减少嵌套并发与共享探测预算；不提前实现全局调度器、自动硬盘识别或设备档位。

## 数据与环境

- 机械盘 / SMB 是首要验证环境；本地 SSD 作为对照，分别记录媒体与数据库所在设备。
- 分开测试冷目录缓存与热缓存，以及媒体事实已齐全与大量缺失；不得用轻量任务热缓存结果代替转换冷路径。
- 每组使用相同作品与初始数据库备份，强制避免计划复用；测量仅写入隔离数据库副本，不转换或修改源媒体。
- 冷缓存状态需要可验证、可复现；未获得合适环境时明确标记未验证，不在共享机器上擅自全局清缓存。
- 基线和候选交替运行至少 5 对；报告中位数、离散情况、每轮结果。小样本不宣称稳定 p95 / p99；尾延迟结论需增加样本。

## 复用现有测量入口

`backend/go/internal/conversion/generation_measurement_test.go` 的 `TestMeasureConversionGeneration` 已支持隔离数据库副本、真实计划会话和扫描阶段计时，可从此扩展。

现有入口固定 1 个生成 worker、顺序执行各轮，候选模式主要比较 selected scan，尚不能测多个同时运行的会话，也未拆分探测、协调计算及持久化。其估算收益不能替代实际并发组合测量。

## 交付物与验收方向

- 分环境、缓存状态、事实完整度与并发组合的测量表，标出实测瓶颈及尚未验证部分。
- 默认会话数、内部作品分析宽度、探测总量的具体建议；明确配置是否仍独立，以及选择理由。
- 无错误、无新增 SQLITE_BUSY / 重试回退、取消与抢占正常；涉及并发机制修改时补充峰值限额与生命周期测试。
- 性能门槛待确认；可复用现有测量入口的“中位数改善至少 5%，5 对中至少 4 对改善”作为候选筛选，最终还需检查单会话延迟及资源峰值。
- 回填前端设置清单：哪些用户控制有实际价值、允许范围及生效时机。现阶段不承诺只开放编码并发或固定其选项。

## 后续待验证

1. NAS 本地 / 受控冷缓存与独立库的同会话复测，确认扫描错峰在目标硬件上的取舍。
2. 更多会话对轻量任务排队有探索性收益；须联合缺失事实负载验证后，再决定会话默认值与探测总预算。
3. 用户控制项继续延后，不依据实验中存在的参数直接开放设置。
