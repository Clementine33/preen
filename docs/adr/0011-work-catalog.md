# 0011 作品目录：作品号身份、来源数据组与派生关系

Date: 2026-09-27

Status: Draft

本仓此前只认识磁盘上的东西：媒体库、目录、文件、转换计划。用户对「这部作品」的评分、收藏与标签无处安放，来源元数据（社团、声优、标签、销量、原作与译作关系）也无处安放。本次新增一层逻辑作品目录：以作品号为不可变身份的作品条目、按数据组导入的来源元数据、作品的目录副本绑定，以及单用户的个人数据。

作品目录是**独立的存储代际（generation 4）**。0008 §3 的规矩不变：旧库拒绝打开且保持原样，操作者换一个数据目录。

## 1 作品号身份与目录名提取

- **规范形是 `RJ` + 8 位零填充十进制数字**，且这是本仓的显式规则：参考实现按数值长度选 6 位或 8 位，于是同一个数字身份会有两个写法。接受恰好 6 位或 8 位的输入，统一升到 8 位，让同一数字只有一个主键值。零编号、其他前缀、长度不为 6 或 8 一律拒绝。
- **目录名提取与单个编号解析是两件事**，且必须能区分「无编号」与「多编号」——扫描要给分类计数，所以提取返回结构而不是布尔值。
- 提取算法是「候选 + 按索引检查两侧」：先用 `RJ[0-9]+` 找出候选（数字串取整段，避免把 9 位串截成合法 8 位前缀），再按索引判断两侧是否为字母数字。**不能用自带边界的正则**：`(?:^|[^0-9A-Za-z])(RJ…)` 会把分隔符吃进匹配，于是 `RJ01234567 RJ07654321` 只命中第一个，多编号目录被误判成唯一作品并绑到错误作品；RE2 无 lookaround，只能走索引法。
- 有分隔的「非法候选 + 合法编号」（如 `RJ0123456 RJ01234567`）判为**多编号**。这是保守选择：宁可解除绑定也不猜。

## 2 目录名是绑定的唯一权威

- 绑定只由扫描维护，且只检查**直接子目录的目录名**——不看文件名、上级路径或元数据标题。恰一个编号才建/复用作品并建立绑定；无编号或多编号解除绑定，目录仍作为普通库存保留。
- 绑定对账在**扫描合并的同一个事务**内完成，落在 `mergeStagingEntries` 的全库分支（成员刷新只处理已验证的当前成员）。因此本次同时修掉 `scan_merge.go` 里 `_ = cleanupStaleEntries(...)` 的错误吞没：库存已变、绑定仍旧的半提交正是对账要消灭的状态。
- 不提供独立创建作品或手工改绑的接口：那会与「目录名是权威」互相矛盾。
- 媒体库根路径实质变更时，在既有更新事务内解除该库全部绑定；等价拼写（`pathnorm.RootPathKey`）不触发。

## 3 统计只留销量，来源单一

- `work_statistics` 只存销量（`dl_count`），**没有来源列**：DLsite 的 dynamic 通道是唯一报告销量的地方，没有第二个来源可供记录，也就没有优先级与覆盖竞争，只剩采集时间新旧判定。数据库用 `CHECK (data_group <> 'statistics' OR source = 'dlsite')` 把这条做成库级不变式，而不是靠处理函数记得。
- 其余统计字段（收藏数、价格与币种、评论数、评分人数、平均评分、评分分布、排名）不入库。它们是同一个上游响应的字段，由调用方在整理载荷时剥离。

## 4 关系与语言版本必须拆成两个数据组

- `translation_info` 两个通道都有（实测逐字段一致），而 `language_editions` **只存在于 static**。若合成一个快照组，只刷 dynamic 时三选一地出错：要么无法提交、要么用空数组误删 editions、要么把旧 editions 重新盖上新采集时间。拆成 `relations` 与 `editions` 两个各自带 `source`/`fetched_at` 的组后，未提交的那组保持原值不动，三个问题同时消失。
- 这不是接口美学：抓取方据此可以高频廉价地只刷统计（一个 dynamic 请求可覆盖约 500 个作品），不必为每次销量刷新重付每个作品一次的、不可缓存的 static 请求。
- 组内语义是**完整规范快照**：未提供的标量显式 `null`，空数组显式表示集合为空。缺字段的上游响应必须由调用方先整理成合规载荷，否则隐式覆盖会把字段抹成未知。
- 按组分化覆盖规则：高优先级来源（DLsite）整体替换低优先级（ASMR.one）；**同来源**之间只接受更新的采集时间。优先级先于时间判定——一份更旧的 DLsite 快照仍然替换更新的 ASMR.one 快照。

## 5 关系分三层：证据、声明边、解析结果

- **自述快照** `work_relation_self`：一行 = 该作品已自述过，无行 = 尚未自述。这两个状态必须分开。`role` 存快照里的**显式**值而非从边推导：原作没有任何出向关系、还没有子作品的父版也没有，边集为空时角色无从还原；`lang` 更不是一条边。
- **声明边** `work_declared_children`：`child_worknos` 展开成行，以便外键与入向索引生效。
- **解析结果** `work_translations`：由前两者按确定性规则算出。自述永远优先于入向声明；自述为空且声明者恰好一个时继承父版；声明者 ≥2 时父版留 `NULL` 并出 `RELATION_AMBIGUOUS` 警告——把冲突写下来并警告，不静默改写也不静默丢弃。
- **派生数据永不阻断删除**：`work_translations` 的两个外键是 `ON DELETE SET NULL`。否则会出现「规则说这个作品可删，数据库说不行」——派生行一旦能当权威，规则就不再是规则。裁决只用证据（副本行 + 别作品的声明或自述），绝不用派生结果。

### 5.1 重算范围与顺序

受影响集**不是**「该作品 + 它声明的子作品」：自述了父版、而父版没声明它的作品同样继承，父版数据到达时必须一起重算。因此：

1. 取**变更前后两份证据依赖图**。两份都要——刷新删掉一条声明时，只有变更前的图还知道那个该清空继承值的子作品。
2. 在**并集**上从变更点**反向**遍历依赖者（沿箭头逆方向），用访问集合去重。证据图**可能有环**（被自述压制的声明仍留在表里），所以它只用来定范围。
3. 按解析规则算出变更后的**有效父边**，**只对有效父边检查环**——证据图里的环不算数。
4. 沿有效父边按父先于子重算受影响作品，旧边已消失的作品同样在这轮里被清回 `NULL`。

拒绝项（400、整单回滚）只针对结构非法：自引用、原作链、有效父链成环、非法编号。**给定同一份已接受证据集，解析是它的纯函数**；但拒绝本身按当时库内已有的自述判定，所以不承诺接受集与提交顺序无关。

## 6 无来源编号的实体按「来源＋作品＋名称」复用

社团、声优、标签优先按「来源＋来源编号」去重。没有来源编号的实体只能在作品范围内识别，故身份键是 `(source, work_id, name)`：刷新时复用同一行而不是每次新建（否则实体 ID 漂移、旧筛选 ID 失效、行数无限增长），且**绝不跨作品按名称合并**（`work_id` 参与身份键）。两个身份由两个 `WHERE` 子句分开的部分唯一索引表达，互不干扰。

作品范围内的实体随作品删除级联消失；导入整体替换关联集合时，同一事务内清掉不再被引用的范围内实体行，避免反复编辑累积。共享实体（有来源编号、`work_id` 为 NULL）一律保留，本次不做自动清理。

## 7 存储形态

- 新表全部是 `STRICT` 表：普通表的类型亲和性会把 `1.5` 静默存进 `INTEGER` 列，光靠 `BETWEEN` 拦不住。必须是整数的数值列（个人评分、销量）再加 `typeof(x)='integer'` 与范围 `CHECK`。个人评分是**整数 1–10**（参考实现注释写 1–5 但从未校验，这是本仓的显式规则）。
- 未知标量一律 `NULL`：成人标记未知 ≠ false，未评分 ≠ 0，销量未知 ≠ 0。
- **新表的时间列由 Go 显式写入定宽 UTC（`2006-01-02T15:04:05.000000000Z`，恒 9 位小数）**，不使用 `DEFAULT CURRENT_TIMESTAMP`。理由：定宽 + 恒 UTC + 恒小数位 ⇒ 文本序等于时间序，`ORDER BY` 能走索引。既有的 `timeFormat`（`RFC3339Nano`）是变精度的，Go 会裁掉尾随零，于是 `…00Z` 的字典序排在 `…00.1Z` 之后；workset 分页正因此在 `WHERE`/`ORDER BY` 用 `julianday(updated_at)`。新列不重复这个陷阱，因此也**不用** `julianday()`。
- `works.language` **不存**：语言是关系属性，唯一真相在 `work_translations.language`，列表投影 JOIN 取。存两份就得在每次关系重算时同步，白白多一个会不一致的地方。
- 副本表不设到 `entries` 的外键：重扫删除库存记录不得连带删除作品或用户数据。
- 列表投影固定返回销量而非来源平均评分；筛选用 `instr` 而非 `LIKE` 做字面子串（`%`/`_` 在 `LIKE` 里是通配符，目录名可以含它们，`scan_merge.go` 已有同类教训）。
- 分页是 keyset 游标，携带排序位置与查询摘要；`limit` 不进摘要（换页大小是合法操作），改筛选或排序后旧游标以 `CURSOR_QUERY_MISMATCH` 拒绝。不承诺跨请求快照，不建服务端分页会话。
- **受支持排序各有自己的索引**，已用 `EXPLAIN QUERY PLAN` 逐个核对：三种排序 × 两个方向都不建临时 B 树。非显然的一处是降序索引的形状——稳定次序 `id ASC` 不随方向翻转，所以降序不能靠反向扫描升序索引得到（那会把稳定次序也翻过来），必须 `((release_date IS NULL) ASC, release_date DESC, id ASC)` 这样的混合方向索引。另外，游标进入未知发售日尾段后结果集内发售日恒为 `NULL`，排序表达式的前两项因此是常量，该分支直接按作品号排序——语义等价，且让计划能走索引而不是排序。
- **个人评分排序是唯一的例外**：评分住在 `work_user_data`（左连接），跨表的排序键建不了覆盖索引，`EXPLAIN QUERY PLAN` 如实显示 `USE TEMP B-TREE FOR ORDER BY`。单用户本地库的规模（千级作品）下这是一次内存排序，可以接受；不为它把评分冗余进 `works` 表（冗余即多一个会不一致的地方）。它与发售日同为「可为空排序」：未评分恒在末尾、不随方向翻转，游标进入尾段后不再携带排序值（空尾段只按作品号续页）。
- 筛选项清单（`GET /circles`、`GET /voice-actors`）只列出至少一部**已列出作品**携带的实体及其作品数，可按 `library` 收窄——与列表的媒体库筛选同一语义，所以清单里的每一项在当前范围内都至少能筛出一部作品。关系占位作品从未出现在磁盘上，不计入。

## 替代方案权衡

- 拒绝把作品号保留成原始输入的写法：同一数字会有两个主键值，同一条作品被建成两条。
- 拒绝用「自带边界」的提取正则：已实测在相邻双编号目录上漏掉第二个编号。
- 拒绝手工绑定/独立创建作品的接口：目录名是权威，第二条创建路径必然与之冲突。
- 拒绝把统计做成多来源并带优先级：DLsite 是唯一来源，多余一列只会带来一个永远空的分支。
- 拒绝把 relations 与 editions 合成一组：两个上游通道的可用性不同，合成后无法只刷其一。
- 拒绝从边推导角色：无出向关系的原作无法还原自己是谁。
- 拒绝让派生关系阻断删除（默认 `NO ACTION`）：已实测复现「规则说可删、外键说不行」。
- 拒绝只按变更后的证据图定重算范围：删掉声明的那次刷新会让旧继承值永久残留。
- 拒绝把证据图当 DAG 直接拓扑排序：本仓允许保存与自述冲突的声明，证据图可能有环。
- 拒绝无来源编号的实体按名称跨作品合并：「同名」不是同一人物或同一社团的证据。
- 拒绝为组合筛选建笛卡尔索引：只建身份、反向关联、副本归属与受支持排序所需的索引。
- 拒绝在列表里逐作品查询标签与副本：成本会随页内作品数增长。
