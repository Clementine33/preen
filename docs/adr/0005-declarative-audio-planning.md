# 0005 声明式规划、稀疏继承、无音效匹配与子树隔离

## 背景

传统的命令式音频处理要求用户配置复杂的“转码/清理/覆盖”步骤开关，容易拼出互相矛盾的步骤；当公共转换策略变动时，若成员配置采用全量拷贝，会导致大量冗余数据或更新脱节。此外，语音作品常伴有无音效、翻转及其他版本子树，若把不同版本的无损音频放在同一作用域内关联，多个无损源会互相阻塞。

## 决定

1. **声明式最终形态规划（Reconcile）**：
   - 用户只需声明各分类期望达到的最终音频规格（如 Opus 档位），规划器比对磁盘事实，自动推导保留、转码生成与过期移除操作。
   - 不做有损升级、有损重编码或将有损转为无损；仅允许已观测的无损源作为生成输入。
   - 输入指纹比对文件路径、大小、修改时间与条目数，不读文件内容；接受保留元数据的改动不可见这一盲点。
   - 未满足的目标（`available_sources` 下原样保留的变体组）与阻塞冲突分开披露，本身不阻止执行。
2. **编码输出的两个判定入口**：
   - 有损输出满足目标，要么由自身实测码率按编解码器的容差答复，要么由**生成记录**证明它是本应用为该目标写下且字节未变的文件。Opus 是 VBR、ffmpeg 原生 AAC 会饱和，实测码率无法裁决它们，生成记录是对应的答案。
   - 两个入口都不接受的文件是未确认，不默认为合格：实测码率不是质量证据，低码率重编码到高目标找不回已失去的内容。
3. **原子组稀疏继承与显式编辑入口**：
   - 成员配置仅保存显式覆盖的原子设置组；缺省组严格继承公共配置，组内不进行递归深度合并。
   - 显式声明空值、显式设置为公共默认值、删除键恢复继承是完全不同的用户意图，系统分别独立序列化保存。
   - 策略槽与外部预设仅在应用时作单次值拷贝，不建立持久的动态活引用。
   - 公共设置、批量编辑与成员编辑是三个显式入口，勾选只是批量动作与浏览的输入，不决定编辑目标；批量编辑只更新被有意改动的组。
4. **版本子树隔离与跨目录无音效关联**：
   - **其他版本子树隔离**：`other_tags` 逐段匹配目录名，从作品根起最外层命中的目录形成独立 Scope，整个子树只属于它。各 Scope 独立聚合音轨与选源，不同版本的无损源不再互相竞争。
   - **无音效（NoSE）跨目录关联**：无音效规则作用于完整相对路径模式，允许在同一 Scope 下将分别存放于 `WAV_NoSE/` 与 `MP3_NoSE/` 的同名音轨精确关联为同一音轨变体，实现精确替换。

## 放弃的方案

- **步骤化指令配置（如先转 Opus、再删原文件）**：难以做严格的一致性前置校验，失败时容易留下半生成状态。
- **配置深层递归合并（Deep Merge）**：排查最终有效值需要逐层回溯合并历史，心智成本过高且容易引发意外覆盖。
- **按实测码率统一比较所有编解码器**：Opus 的 VBR 与 AAC 的饱和会让规划永远重建自己写出的输出；放宽容差也解决不了，生成记录才是答案。
- **未满足目标阻塞执行**：它不改变任何文件，用户应当看到它，而不是被它挡住。
- **选中即编辑目标**：一次无意的勾选会改掉某个成员的配置。
- **读取音频内容识别无音效**：长作品中稀疏音效差异的读取成本不符合快速规划的目标。
- **将所有其他版本合并进单一作用域**：不同版本的无损源仍会互相阻塞；强制挑一个源则掩盖了内容版本冲突。

## 后果

- 用户遇到无法自动解决的多源冲突时，必须显式在界面配置或调整版本隔离规则后重新生成计划。
- 完整规则语法、策略模式及生效值计算细节见 [conversion.md](../api/conversion.md) 与 [policies.md](../api/policies.md)。
