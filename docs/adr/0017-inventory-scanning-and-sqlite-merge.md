# 0017 库存扫描：作品级调度、完整观察集与按变化合并

扫描支持多层分类下的独立作品，以扫描确认的作品根作为处理边界。优化沿用 SQLite 平铺路径库存、完整 staging 和原子合并，先落实作品级有界调度，再减少数据库冗余索引及无变化写入；最后修正绑定清理的 SQL 参数数量上限。本记录收敛本轮已采用的路线与验收依据，扫描吞吐调优至此结束。

作品号及副本身份由 [ADR 0011 §1–2](0011-work-catalog.md) 定义；连接与事务沿用 [ADR 0008 §5](0008-database-self-cleanup-and-retention.md)，开发 schema 与发布迁移边界沿用 [ADR 0013](0013-development-schema-and-release-migrations.md)。本记录不改变这些决定。

## 1 作品级有界扫描与库存事实

### 优化前后实现对照

“优化前”指提交 `b899386f9d9b3fd88fd0e30d2382e0560551e980` 中的原始实现；它与后续各项优化的测量基线不同。原实现逐个调度目录：worker 读取一层并把子目录交回协调器，协调器继续投递各层目录，并非按作品分配完整子树。

| 维度 | 原始实现 | 本轮最终实现 |
|---|---|---|
| 扫描单位 | 每个目录都是任务，同一作品内部也并发下探 | 分类发现＋作品任务，作品内部顺序扫描 |
| 调度与积压 | 默认 4 个目录 worker；通道有界，协调器的待投递路径切片没有固定容量上限 | 默认 32 个作品 worker；发现直接投递容量 `2 × workers` 的队列，满时等待 |
| 目录读取与属性 | `os.ReadDir` 排序，逐条 `Info()` | 保留相同读取与属性语义 |
| 作品边界与绑定 | 无作品根标记，只根据仓库直接子目录名称绑定；深层作品不绑定 | 持久化 `is_work_root`，任意深度作品根绑定，内部 RJ 子目录不另立作品 |
| 不变 entries | staging 全部进入 upsert，无条件冲突更新，重写 scan_id、updated_at | 先增加条件更新，再提前到 SELECT 过滤；不变且无需清 dirty 的行不写入 |
| 合并统计 | COUNT 本轮 scan_id 对应的 entries，依赖每行都被重写 | COUNT 本轮完整 staging，保持观察条数语义 |
| 内容版本与媒体事实 | size、mtime 改变触发失效 | 同时覆盖文件／目录类型改变；其他观察字段变化保留媒体事实 |
| staging 索引 | 主键外还有 session、status 两个索引 | 删除两个冗余索引，保留 `(session_id, path)` 主键 |
| 剩余后代查询 | 使用 `substr` 比较路径前缀 | 改为二进制路径索引范围，自身按接口语义单独处理 |
| 绑定写入 | 每个副本两次 Exec，冲突时也执行相同值更新 | 每事务复用两条 Prepare，只提升未收藏作品或修正变化的 work_id |
| 失效绑定清理 | 将所有 bound 路径展开为 SQL 参数，超过 32,765 个根会触及默认上限 | 事务临时集合＋分批插入，清理语句只绑定 library_id |
| 存储与提交 | 平铺 entries、完整 staging、WAL、同事务合并与绑定；entry 缓冲 100、批次 1000 | 保留这些机制与容量，不采用变化行 staging 或 pragma 调整 |

功能与正确性变化是多层作品边界、按实际写入记录行版本，以及解除绑定参数上限；性能依据则是第 3 节逐项与当时当前基线比较的结果。没有原始方案与全部改动后的最终方案在同会话、同功能范围下的完整 A/B 数据，因此不计算总体提速百分比，也不累加各项收益。

### 扫描边界与失败语义

一个发现过程逐层读取分类目录，遇到首个含单一有效 RJ 编号的目录即输出作品根，投递给 worker。worker 顺序读取该作品全部内容，内部 RJ 子目录不另立作品。发现与扫描重叠，作品任务队列容量为 `2 × workers`，不预先收集全库作品路径。分类、普通文件及未绑定目录仍入库存；每一层的 `Delete/` 回收子树在读取属性和下探之前跳过，不入库存、不计入扫描进度，后续完整扫描会清理旧扫描留下的回收库存与副本绑定（[ADR 0018 §1](0018-work-local-recovery-directories.md)）。仓库根本身不输出，目录符号链接不下探，作品根只输出一次。

采用名称排序的 `os.ReadDir`，逐条读取 `Info()`。默认 32 个作品 worker，`scan.workers` 可调低，上限 32；entry 缓冲保持 100、写入批次 1000、默认 GC。成员刷新顺序扫描一个已验证作品，并保留作品根标记。conversion 生成使用同样的顺序作品遍历，多个选中作品有界并发，共享一个 staging writer 和一次显式范围事务；目录自身标记、未选库存、绑定及未变化媒体事实保留。空范围不清理，selected 会话禁止进入依据空 scope 的完整 merge。采用依据见 [ADR 0019 §4](0019-conversion-execution-and-selected-generation.md)。展示顺序由查询及界面明确排序，不依赖并发扫描的输出顺序。

`is_work_root` 写入扫描条目、staging 与 entries，作品根查询使用部分索引 `(root_path, path) WHERE is_work_root=1`。完整 merge 根据库存事实在同一事务维护任意深度的 `work_copies`；局部刷新不重新识别分类或作品身份。路径查询使用二进制后代范围 `P + "/" <= path < P + "0"`，自身按接口语义另行处理，保留原始大小写、Unicode、`%` 和 `_`。

扫描失败或取消不进入 merge，按现有机制尝试清理 staging，不以部分观察删除或覆盖旧库存；merge 内任一步失败均回滚。完整扫描、成员刷新及公开 SSE 会话语义保持一致。

### 默认值的依据与限制

NAS 本地 HDD 为遍历选择环境，SMB 只回归最终实现。首次 A/B/C 全流水线比较使用相同有界作品调度、空库和生产 staging/merge：

| 配置 | 冷完整流程 s |
|---|---:|
| 16 worker＋排序 | 7.627970 |
| 32 worker＋排序 | 6.717681 |
| 32 worker＋保留目录返回顺序 | 6.677796 |

两种 32 配置首测差约 0.6%，未形成原生顺序的稳定收益证据，按事先约定的接近时规则保留 32＋排序。这是工程默认值，不是排序最优的证明；目录返回顺序也不等于物理磁盘顺序。该阶段深层副本绑定为 **0**，这些耗时不作最终 940 副本流水线的基线。

## 2 按顺序落地的数据库改动

1. **保留完整 staging，合并只更新有变化的 entries。** 使用 NULL 安全比较观察字段与 dirty 状态。大小、mtime 或文件／目录类型变化增加 `content_rev` 并失效媒体事实；其他观察更新保留媒体事实与错误状态。内容不变但 `dirty_flag=1` 的条目仍更新以清理 dirty。不变且无需清理的行保留原 `scan_id`、`updated_at`；`Merged` 仍是本轮 staging 的 COUNT。
2. **删除两个冗余 staging 索引。** 移除 `idx_staging_session(session_id)` 和 `idx_entries_staging_status(status)`；会话筛选、计数、清理及 merge 子查询使用既有主键 `(session_id, path)`，不增加宽索引。
3. **把不变行过滤提前到 SELECT。** `mergeObservedEntriesSQL` 在 LEFT JOIN 后按新增行、观察字段差异或 `e.dirty_flag IS NOT 0` 筛选，保留原 `DO UPDATE WHERE`。比较涵盖 root、parent、name、类型、作品根标记、size、mtime、format；format 使用 `NULLIF(s.format, '')`。该谓词排除的恰好是原冲突更新会跳过的行；内容不变时 excluded dirty 为 0，会话内 path 唯一，不产生行间影响。
4. **作品与副本绑定跳过空写，复用语句。** works 只在 `collected_at IS NULL` 时执行原 COALESCE 更新；work_copies 只在 work_id 不同时更新。两条 upsert 在合并事务内各 Prepare 一次。已收藏时间保留，同路径作品号变化仍修正绑定，副本 ID 与 created_at 保持稳定。
5. **解除绑定不再展开全库参数列表。** Go 的编号与恢复路径分类仍为权威；非空 bound 写入事务内 `TEMP ... WITHOUT ROWID` 表，每次最多 1000 个参数，再用 `NOT IN (SELECT rel_path ...)` 清理该库失效副本，成功后 DROP。空集合保留直接清理该库副本的分支。失败由原事务回滚，不引入持久表或迁移。

所有改动保留 staging 全集。过期删除、COUNT 与绑定同步仍由完整观察及合并后的库存决定，未改写“本轮没看到什么”的证明方式。

## 3 采用改动的数据依据

### 样本、计时与验收方法

真实 NAS 样本：28,839 entries，其中 5,760 目录、23,079 文件、940 作品根／副本。媒体在 HDD/Btrfs（`compress=zstd:3`）；SQLite 在 LXC ext4 卷，经 pve thin pool 映射到 NVMe。测量不读取媒体正文或启动分析，扫描、staging 和 merge 分开记录；walk 含背压，staging 与 walk 重叠，耗时不能相加。

SQL 改动采用本机 `BenchmarkMergeStaging/{cold,warm}`：确定性生成同规模条目，路径平均 98.95 B；使用生产驱动、DSN 和文件数据库。每操作独立建库，准备 staging、预置库存及校验都在计时外，**只计 MergeStaging**。cold 是空 entries，warm 是相同条目已入库，不表示 OS 缓存冷热。TMPDIR 显式放在 NVMe/Btrfs，未使用本机 tmpfs `/tmp`。测量版本为 Go 1.27.1、modernc.org/sqlite v1.59.0／SQLite 3.53.4。

每侧十个样本，预编译两份产物，奇数轮 baseline→candidate、偶数轮反序，`-benchtime=1s`；benchstat 作独立两样本比较。性能改动事先登记：warm 中位数下降且 p<0.05；cold 中位增幅≤2% **或** p≥0.05。非显著不等于证明等价，各次结果只与本次当前基线比较，不能跨实验直接相减。

### 对落地决定有用的结果

去索引的 NAS 热扫每侧三次，固定先 before 后 after：staging 累计均值 **673.350→594.801 ms（−11.67%）**，完整流程 **1.651059→1.654664 s（＋0.22%）**。EXPLAIN 确认所需查询仍用 staging 主键前缀；采用理由是索引冗余与写入成本，未宣称整轮提速。该组未交替执行，次序与数据库页状态变化未被隔离，仅作为本组观测。

随后三轮 NAS merge 诊断中，热重扫 entries 实际改动均为 0；热完整流程均值 **1.297522 s**，merge **0.673677 s（占 51.92%）**，upsert **338.484 ms（占 merge 的 50.24%）**。这决定了下一步验证 SELECT 提前过滤。

以下是正式本机门槛的**整个 merge**中位数，不是 upsert 单步或 NAS 全流程成绩：

| 已采用改动／库存状态 | 本次 baseline ms/op | 候选 ms/op | 变化 | benchstat p |
|---|---:|---:|---:|---:|
| SELECT 过滤／空库 | 369.781 | 371.349 | ＋0.42% | 0.247 |
| SELECT 过滤／不变重扫 | 283.799 | 179.442 | −36.77% | <0.001 |
| 绑定空写过滤＋Prepare 复用／空库 | 369.379 | 347.990 | −5.79% | <0.001 |
| 绑定空写过滤＋Prepare 复用／不变重扫 | 178.462 | 155.239 | −13.01% | <0.001 |

两组均通过预登记门槛；绑定组基线已包含 SELECT 过滤，未分别测两个谓词与 Prepare 的独立贡献。

SELECT 通过后做一组 NAS 冷＋热正确性确认。绑定改动另做同会话 baseline→candidate→candidate→baseline，每次独立空库，宿主机先唤醒 HDD、确认 active/idle、sync、清缓存，再扫描并紧接热重扫。事先登记的冷完整流程门槛为候选均值≤当前基线均值×1.05，结果通过；这是不回退验收，不宣称历史原型到当前实现的冷提速。

这些 NAS 验收均确认观察与库存一致、940 作品根与副本、同库冷热 `(rel_path, copy_id, work_id)` 稳定、会话 completed、staging 清空及热 entries 改动 0。上述落地验收中的 Go 测试与 lint、dirty 清理、content_rev、媒体事实、失败回滚与取消回归均通过。

### 规模修正的独立依据

旧绑定清理使用 `len(bound)+1` 个 SQL 参数，受默认 32,766 上限约束。本次用 **32,767 个有效作品根**经真实 MergeStaging 入口先复现 `too many SQL variables`，修正后合并成功、失效绑定删除、有效旧副本 ID 保留。

性能回归仍用 940 根 fixture，每侧十样本。空库 merge 中位数 **350.669→349.465 ms，p=0.853**；热重扫 **155.780→155.753 ms，p=0.796**，均通过事先登记的“增幅≤2% 或 p≥0.05”不回退门槛。这是正确性修正，不作为提速成果，也没有测 32,767 根的吞吐。

## 4 保持的策略与收尾边界

目标 LXC ext4 卷上的 pragma 诊断使用 SELECT 过滤、优化前绑定和合成空库；FULL/NORMAL × cache −2000/−32000 四条件各十次，未登记 pragma 落地门槛。默认 cache 下 merge 中位数 FULL **587.355 ms**、NORMAL **598.329 ms**，未观察到 NORMAL 提速；FULL＋较大 cache 为 **547.404 ms**，只验证了合成样本，没有真实流水线及连接内存预算验收。产品保留已读回确认的 WAL、synchronous=FULL、cache_size=−2000、wal_autocheckpoint=1000，不改变持久性策略。

相对历史原型的冷扫描提升未达成：原型不含最终绑定且环境时点不同，已不作为门槛。以后若有实际需求改动冷路径，使用同会话的当前流水线基线、预登记门槛、前后交替、唤醒与宿主机清缓存；SMB 继续作为回归环境。宿主机缓存清理不保证清掉硬盘内部缓存，本机空库 merge 基准不替代 HDD 全流水线验收。

本轮停止吞吐调优。保留手动 BenchmarkMergeStaging，不增加 CI 性能门禁。放弃只写变化行的 staging：它需要改变过期删除的完整观察依据，本次不承担该语义改造。缓冲、双缓冲 writer、GC、对象池、mmap、并发矩阵、目录顺序、WalkDir 替换和 pragma 调整均不列为本轮后续工作；不引入 ORM、路径字典、层级闭包表，也不以祖先目录 mtime 跳过深层库存。

本记录内列出决定所需的数据、测量方法及验收结果。实验异常、未确认原因及历史待测建议不构成这里的架构依据。
