# 计划生成与内部并发调优

整理日期：2026-10-17
状态：已完成三轮实测与调优。默认计划生成并发定为 `GenerationConcurrency = 2`，配合固定宽度 1 的轻量规划通道与跨会话单扫描槽；内部作品分析宽度（4）与缺失码率探测宽度（4）保持不变。

详细实测数据与各轮演进见[计划生成并发：SMB 实测与调优过程](generation-concurrency-measurement.md)。

## 目标与边界

单独验证计划生成并发和任务内部并发的组合，确定默认值及资源边界，再决定是否向用户开放修改。不把“已有配置键”或某层 worker 数直接当作性能收益依据。

- **优先级**：机械盘 / SMB 上单个计划的响应与资源稳定优先，多计划总吞吐次之。不得仅凭总吞吐提高接受单计划明显变慢。
- **范围**：以转换计划生成为主路径，覆盖计划会话、扫描、作品分析和文件补测，同时验证轻量重命名、元数据计划的排队影响以及后台媒体事实探测的抢占。编码执行另行调优，本议题保留其现有参数和安全边界。

## 当前并发层级与定案

| 层级 | 当前宽度 | 作用与叠加关系 |
| --- | --- | --- |
| 通用计划会话 | 默认 2，可配置 | 跨 kind FIFO；允许完整生成请求重叠，不能加速单个请求 |
| 声明的轻量计划 | 固定额外 1 | 重命名与元数据可使用；通用 worker 仍可认领，未声明 Task 不进入 |
| 转换前库存刷新 | 每次 walk 默认 32，可配置；跨会话单扫描槽 | 作品级遍历，随后 staging / merge；等待扫描槽仍占通用 worker |
| 单个转换计划的作品分析 | 固定 4 | 库存读取、补测与协调计算 |
| 单个作品的缺失码率补测 | 固定最多 4 | 只探测未知码率；调用媒体探测，必要时回退 ffprobe |
| 后台媒体事实探测 | 默认 8 | 独立池，可被用户任务抢占；不能直接套用为前台补测的限额 |

在补测阶段，默认组合理论上可能达到 `2 × 4 × 4 = 32` 个探测调用。扫描与分析是前后阶段，不能把 32 个扫描 worker 再乘进这个数；不同会话处于不同阶段时仍可能同时争用磁盘。

## 三轮调优结论摘要

1. **第一轮（基础链路与扫描错峰）**：
   - 修复每次新建 SQLite 连接重复设置文件级 `auto_vacuum` 导致的读连接阻塞（`SQLITE_BUSY`）。
   - 优化选中范围合并（Merge）SQL，移除每个 scope 的全表范围重建，单计划 Merge 耗时由 1.781 s 降至 0.237 s，单计划总耗时下降约 52.7%。
   - 引入转换输入刷新跨会话单扫描槽，多会话共享磁盘压力下的遍历并发峰值由 64 降至 32，整批耗时下降约 54.5%。
2. **第二轮（轻量规划通道与冷/热缓存多会话对比）**：
   - 新增 `LightPlanner` 专用 worker（宽度 1），在两个重型转换并发时将重命名与元数据热缓存响应从 1.7~1.9 s 降至 0.38~0.55 s。
   - 在 74 个成员目录（23,094 个文件，约 71.36 GiB）数据集上完成 240 个热 / 冷缓存样本对比：N=4 在缺失事实压力下虽略微缩短整批时间，但冷测探测峰值翻倍（32→64）且首请求变慢，故不提高默认值。
3. **第三轮（实际单库部署补测与定案）**：
   - 实际部署中媒体库位于同一机械盘，单库单一 Workset 且同一 Operation 至多一个活跃生成会话（即同时至多 1 个转换计划）。
   - 在“1 转换 + 1 重命名 + 1 元数据”真实负载下，N=1 与 N=2 整批耗时无一致差异；但 N=2 提供第 2 个通用 worker 与轻量 worker 并行认领两项轻量任务，使元数据排队几乎消除（热测完成时间缩短 40.7%，冷测缩短 52.5%），仅在热测下增加约 63 ms 重命名耗时。因此定案保留默认值为 2。

## 测量入口

`backend/go/internal/conversion/concurrency_measurement_test.go` 的 `TestMeasureGenerationConcurrency` 使用静态备份和私有数据库副本，支持多工作集、会话数、事实缺失、同目录压力及真实重命名 / 元数据计划。

旧 `TestMeasureConversionGeneration` 比较串行 fallback 与 selected scan，仍可用于该差异的测量，不替代并发组合对照。

## 已知边界与后续约定

1. **冷缓存 I/O 边界**：热缓存下轻量任务均稳定在亚秒级（< 0.4 s）；受控 OS 冷缓存下目录与存储 I/O 仍占主导（单库冷测元数据中位数约 1.345 s），保持轻量通道宽度 1，不靠堆叠 worker 掩盖冷盘延迟。
2. **多盘串行扫描边界**：跨会话单扫描槽不按物理设备区分，双独立 HDD 同时提交转换计划时扫描阶段会串行化（热 / 冷整批耗时分别增加约 90.4% / 65.5%）。在单盘部署下无影响，不引入设备拓扑识别。
3. **配置暴露策略**：内部并发宽度与生成会话并发保持后端配置与默认值，暂不向前端暴露多余调优项；编码执行池单独调优。
