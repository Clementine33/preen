# 0002 直接文件管理、全局准入互斥与作品同级回收目录

## 背景

在引入直接文件管理之前，唯一的磁盘写路径是转换计划执行。用户改名、移动或清理孤立文件也必须生成并执行完整的转换流水线。此外，媒体库各成员根可能物理重叠，若缺少严格的写入协调与边界防御，用户操作容易引发跨成员污染或同名目标覆盖。

## 决定

1. **第二受控写入路径**：在计划执行之外开放直接文件管理接口，支持成员内的单项重命名、单项移动以及批量软删除，不新建目录。未知操作、不可用成员、非法路径、空项或多项都拒绝整个请求，此时没有任何项被执行。不跨成员移动、不做跨文件系统复制后删除，也不操作成员根。
2. **进程级全局准入互斥**：
   - 任何扫描、排队中或运行中的任务生成与执行，都会拒绝直接文件管理；直接文件管理持槽期间同样拒绝启动上述后台任务。媒体库换根与删库共享该槽位。
   - 检查与登记原子完成，忙时直接返回 409（`BUSY`），不设隐式等待队列。写入完成后的受影响目录库存同步复用当前持有的准入槽，避免重入自锁。
3. **严格的路径边界与无覆盖保证**：
   - 后端独立校验源与目标：拒绝绝对路径、相对路径越界（`..`）以及符号链接逃逸。
   - 不覆盖同名目标，采用目标系统的不覆盖原语。唯一例外是只改字母大小写的重命名：在大小写不敏感的文件系统上目标「已存在」的正是源文件本身，此时直接改名，不按 `TARGET_EXISTS` 拒绝。
   - 移动操作接受显式 `"."` 记号表示目标为成员根，缺省或空字符串严格拒绝。
4. **逐项执行、首错即停与结果权威性**：
   - 批量软删除按序执行，首个条目失败后立即停止后续处理，已完成项不自动回滚；父目录与子项同时选中时仅操作父目录，子项标记为被父项覆盖。
   - 接口同步等待磁盘操作与库存刷新，返回明确的逐项执行状态，拒绝前端乐观更新。若写盘成功但刷新失败，两者分别汇报，不自动重放写操作。
5. **作品同级回收布局（Delete 目录）**：
   - 软删除及计划替换后的文件统一移入与作品根同级的 `Delete/`（即 `<作品父目录>/Delete/<作品目录名>/<作品内部相对路径>`），重名时自动递增数字后缀防碰撞。
   - 所有层级的 `Delete/` 均作为保留子树，库存扫描与成员选择直接排除，回收内容不会重新进入作品库存。

## 放弃的方案

- **路径级锁管理器**：媒体库根路径可能重叠，符号链接与目录嵌套判定复杂；引入细粒度路径锁代价过高。接受「其他媒体库忙时暂时不能整理文件」的代价；只有实际使用证明全局互斥不可接受时再评估。
- **前端禁用按钮代替后端准入**：前端无法防御多标签页或绕过界面的 API 调用，互斥与校验必须在后端原子完成。
- **库根集中回收目录**：对于深层嵌套分类下的作品，集中回收到媒体库根会抹去作品所属分类上下文，增加人工恢复定位成本。
- **空字符串表示成员根**：字段缺省或解析疏漏容易被误判为“移动到根”，显式 `"."` 记号语义明确且防呆。

## 后果

- 媒体库扫描或大批量转换执行期间，用户无法执行直接文件整理。
- 外部进程绕过应用直接修改磁盘不在进程互斥保证范围内（必须依赖后续扫描同步）。
