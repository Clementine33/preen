# 0018 深层作品的同级回收目录与扫描排除

媒体库允许分类目录下的深层作品根，集中写入库根 `Delete/` 会把回收位置移离原作品分类。本记录替换 [ADR 0002 §1](0002-direct-file-management-and-admission.md) 的库级回收位置及回收库存刷新规则，其余文件管理与准入约束沿用原决定。

## 1 回收位置与库存边界

conversion 中被替换或废弃的音频、直接文件管理中的软删除均进入 `<作品父目录>/Delete/<作品目录名>/<作品内部相对路径>`。例如库 `foo` 中 `bar/RJ000001/disc/track.mp3` 回收为 `bar/Delete/RJ000001/disc/track.mp3`。单层作品的路径保持原约定，软删除重名仍不覆盖，沿用数字后缀。

`Delete` 是每层的保留回收目录名；扫描在读取属性及下探之前跳过它和全部后代，成员选择、浏览及副本绑定也拒绝这些路径。Windows 路径按大小写不敏感比较，POSIX 路径按精确名称比较。回收文件保留在执行与文件管理结果中，但不进入库存；执行只同步已移除源与已提交输出，直接文件管理只刷新原成员。

原库根的旧回收目录不搬迁，也继续被扫描排除。下一次成功完整扫描清理旧回收库存及失效副本绑定；取消或失败沿用完整观察集的原子合并语义，不删除部分扫描未看到的旧库存。逻辑作品与用户数据沿用原副本解绑规则。

## 2 拒绝的替代方案

不集中到库根：深层作品的回收目录应留在同一分类旁，便于定位与恢复。不仅排除库根 `Delete/`：各分类的新回收目录同样会制造重复副本与遍历成本。不搬迁已有回收媒体：历史结果仍指向原位置，改规则无需额外磁盘迁移。
