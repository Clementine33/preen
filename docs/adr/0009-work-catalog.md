# 0009 作品目录身份、外部关系报告、库存扫描与用户资料

实施状态：2026-10-23 已实现独立关系报告、报告唯一新鲜度、事务内结构校验与派生更新，以及作品删除保留报告和外部关系编号。已移除占位创建与旧接口字段，扫描是唯一新增入口并复用已有报告，收录时间必填且重扫保留首次时间；父链补抓只写独立报告。已实现详情只读快照、确定关系树、外部轻量节点与安全来源链接；已实现按类别选择的作品及共享来源实体手动清理、所选作品删除后的引用预览、事务内保护重检与级联计数；已实现报告依赖不动点保留、无根强连通组回收、有限候选边界及逐批事务内重检和结构校验。外部契约随实现更新。

## 背景

系统在底层仅管理文件与目录，但用户心智需要跨媒体库的逻辑作品概念（评分、收藏、标签、来源元数据）。早期的库存扫描与绑定机制存在深层嵌套路径查找慢、扫描大库时 SQL 参数超限、以及重扫时级联误删用户个人资产的风险。

## 决定

1. **唯一规范化作品号身份与目录权威**：
   - 作品号以标准 8 位零填充字符串（`RJ00000000`）为主键；输入 6 位或 8 位均提升为规范形。
   - 物理目录名是绑定的唯一权威事实。分类发现自顶向下逐层读取，遇到首个包含单一合法 RJ 号的目录即确立为作品根，该目录下所有内容归属该作品，内部即使再有 RJ 子目录也不另立作品；多编号目录不猜测绑定，继续向下发现。
   - 不提供手工改绑或脱离目录凭空创建作品的接口，避免与物理磁盘事实冲突。
   - 首次扫描的收录时间只保存为 `collected_at`，重扫不改写；不再重复保存与其相同的 `works.created_at`。
   - 作品目录的新增入口只有扫描，`collected_at` 设为 NOT NULL；来源提及不能通过填入假收录时间创建作品。来源提及的原作、版本页或译作编号作为外部引用，不再为了保存关系创建占位作品；同一编号以后被扫描时，建立作品条目并复用已有关系事实。
2. **重扫防级联与完整观察、未变目录直属文件沿用**：
   - 作品表与用户个人数据不通过外键硬级联到具体文件条目。即便物理文件暂时丢失，作品实体与用户收藏数据依然保留。
   - 扫描先建立完整观察集，再原子合并；只有完整、成功的扫描才能清理旧库存，出错或取消不以残缺观察删除历史数据。
   - Library Scan 逐层确认每个目录，未变目录的直属文件可按已观察沿用：库存 mtime 必须大于 0、等于本轮观察值，并严格早于上次保留的成功全库扫描开始时间减 10 秒。不存在该扫描记录时全部重读；Full Rescan、成员刷新与所选范围扫描始终完整读取。
   - 目录 mtime 只有与直属条目的完整列表一同观察才可写入，包括直接取属性的库根。补建父目录与执行祖先写 0，未观察属性的成员根刷新后写 0；改名或搬移只改路径，保留目录 mtime。
   - 叶目录满足条件时不打开；非叶目录仍读取列表，用列表自带类型核对直属条目的「名字＋是否为目录」。完全一致才沿用直属文件、只对子目录取属性并继续遍历；不一致就重新观察全部直属条目。沿用只保护直属文件，不保护子树，已测媒体事实保留，进度包含沿用文件；库根始终是分类边界，不因其名称成为作品根，也不新增目录进度。
   - 10 秒边距覆盖上次观察时的秒级精度、属性滞后与小幅时钟偏差，不保证本轮客户端属性缓存已刷新。以客户端与 NAS 的 NTP 时钟同步为前提，不增加强制刷新属性的网络往返。
3. **差异合并与失效绑定清理**：
   - 合并时通过 SQL 比对仅对真实新增、内容变化（大小、mtime、类型变动）的条目触发写盘与更新，未变动条目保留原事实与已提取的媒体元数据。
   - 清理失效绑定时使用事务内临时集合加分批插入，清理语句只绑定 `library_id`；此前把所有已绑定路径展开为 SQL 参数，超过约 3.2 万个作品根会触及 SQLite 默认参数上限。
4. **来源元数据按完整数据组（Data Group）原子更新**：
   - 来源数据切分为 `core`、`statistics`、`relations`、`editions` 四个独立数据组。
   - 核心元数据保存主封面 `cover_url` 与独立的样图地址；远程缩略图地址由 HTTP 展示层按已知来源规则派生，未知地址回退主封面，不保存或导入独立 `thumbnail_url`。
   - 更新时按组全量覆盖，未提交的组保留旧值。高优先级来源（DLsite）整体替换低优先级（ASMR.one），同来源之间只接受更新的采集时间；优先级先于时间判定。销量只有 DLsite 报告，`statistics` 组不设来源列，由库级 CHECK 约束保证。
5. **来源实体身份、独立关系报告与可重建的派生结果**：
   - 社团、声优、标签优先按「来源＋来源编号」去重；没有来源编号的实体以 `(source, work_id, name)` 为身份，刷新时复用同一行，不跨作品按名称合并。
   - 关系报告按声明主体的规范编号独立保存来源、抓取时间与自述／子项证据，不以主体或引用目标在作品目录中存在为前提。报告内子项属于该报告，但外部编号不形成对作品条目的存亡约束。
   - 译作关系由自述与入向声明按确定性规则解析；声明者不唯一时父版留空并发出 `RELATION_AMBIGUOUS` 警告。解析可以经过未收录的外部编号，只为目录中已有作品保存派生结果；结果的原作与父版本目标可以是外部编号，不能因目标没有作品行而断开链路。
   - 外部关联页面仅保留编号、语言、关系和来源外链，不持久化完整标题、封面、标签或销量，也不提供本地完整作品详情。作品目录与外部报告共用规范编号，不另造第二套身份。
   - 手动清理保护仍有副本（含离线库绑定）或个人资料的作品；用户词库保留，关系引用本身不强迫保留无副本、无个人资料的完整作品条目。必要报告以全部存续作品为根，沿有效父链保留节点的自述与所有入向声明所属报告，不沿原作编号扩展。为维持全证据集结构校验，继续计算已保留报告主体的解析依赖直到集合稳定，不能忽略声明者的自身依赖。清理前后存续作品的解析与冲突诊断保持不变，剩余证据仍合法；无用途互引报告可整体回收，子项列表不把所有兄弟子项变成保留根。报告按依赖先删依赖者，强连通组不可拆分；每批保护当前存续作品和本批之外报告的依赖闭包，再验证删除后全证据集，避免并发新增依赖或自述删除激活旧声明造成非法中间状态。新报告不进入本轮有限候选集合，竞态下不能安全删除的旧候选跳过。
   - 正常版本树只展示确定的解析关系；未采用的原始声明不能混入正常归属。中间版本页未收录不代表可以跳过它，B → X → A 仍保持父版本 X、原作 A。详情通过同一只读快照组装关系、版本列表、诊断、目录存在性、副本状态、目录导航所需媒体库根路径和本地封面引用；并发写入可继续提交。固定三语言版本树之外，轻量关系节点集保留未知语言的有效祖先链，来源外链由规范编号构造，不信任抓取 URL。
6. **作品合集保存用户意图，Favorites 只有一个来源**：
   - 作品合集是应用级的有序 Work 集合，与媒体库、副本和库存条目解耦。同一作品可属于多个合集，同一合集内不重复；副本丢失、重扫和媒体库删除均不清除成员关系。
   - 内置 Favorites 的成员关系就是现有 `favorite` 标记。旧收藏写入、列表筛选和详情读取都使用该关系，不再保留另一份布尔字段。发布升级按旧更新时间及作品号保留原收藏集合与顺序。
   - 合集成员是明确的用户收藏意图，阻止彻底删除 Work；删除保护在事务内检查并列出合集引用，同时由外键兜底。单条删除与批量清理统一保护评分、非空备注、用户标签、合集、收听位置和听完记录；须先明确清除个人资料才能删除作品。
   - 编辑通过追加、移除和相对目标移动表达增量意图，在当前状态的写事务内执行；首版不引入整表覆盖、乐观锁版本或分数索引。
7. **收听位置是按演绎版本（Rendition）存储的快照，曲目由客户端推导**：
   - 每个 (Work, Rendition) 一行，覆盖写：曲目 key、轨内秒数、该曲目在版本内的序号与总数、完成时间与更新时间。不保存文件、格式、副本或播放队列，因此转换与格式偏好变化不使其失效。
   - Rendition 与曲目 key 由前端的曲目推导给出，服务端只存不算；序号与总数是写入时的展示快照，下次写入即自我校正，定位始终依靠 key。
   - 完成按 Rendition 声明，作品级「听完」由任一版本完成派生，版本之间不互相同步。推导结果漂移留下的孤儿行在续播时忽略，不做自动清理。

## 放弃的方案

- **重复保存作品创建时间和远程缩略图地址**：扫描是唯一新增入口，创建时间与收录时间相同；缩略图是主封面的展示变体，独立存储会增加同步方向。
- **基于文件内容或元数据猜测作品绑定**：缺乏确定性，容易把相同声优或相近标题的作品绑错。
- **增量暂存（只把变化项写入 Staging）**：无法证明哪些历史文件已经在磁盘上被物理删除，从而失去可靠清理失效库存的能力。
- **按目录 mtime 跳过整棵子树**：深层文件增删不会改变祖先 mtime，必须逐层检查目录，不能把父目录未变等同于子树未变。
- **只沿用叶目录**：仍读取非叶目录文件的 inode。2026-10-25 的同调度器冷缓存机械盘探针中，叶目录沿用约 30 秒、14.7k 次读取，非叶也沿用约 15.5–15.6 秒、8.9k 次读取；SMB 两者约 7 秒，差异在噪声内。
- **不读列表、逐个查询库存子目录属性**：SMB 每个子目录各一次往返；同次探针约 7.2–9.3 秒，未优于列表带回子目录属性的约 7.2–7.9 秒。冷机械盘约 15 秒，与读取非叶列表相当，未换来额外收益，且失去名字与类型核对。
- **作品级封存后跳过整棵作品**：增加需要用户理解和维护的封存状态，作品内部变更仍会漏掉，不能替代逐层确认。
- **文件系统监视**：网络挂载与离线期间没有可靠、统一的变更历史，恢复后仍需要扫描，增加第二套状态不能消除本轮成本。
- **stat 层面的微优化**：SMB 的 readdir 已缓存属性，实测带／不带 lstat 为库 A 20.9／20.1 秒、库 B 6.6／6.1 秒；冷 Btrfs 上 inode 顺序也没有收益，不引入 `AT_STATX_DONT_SYNC` 或平台排序路径。减少文件属性观察才是有效的读取削减。
- **跨作品按名称合并无来源编号的实体**：同名不同人的声优或社团会被合成一个，筛选结果随之错误。
- **让派生关系阻断删除（默认 `NO ACTION`）**：已实测复现「规则说可删、外键说不行」，派生行一旦能当权威，规则就不再是规则。
- **为每个关联编号创建占位作品**：把外部关系知识和已收录作品混在同一生命周期中，祖先补抓会扩大作品资料存储，互相引用又妨碍回收。独立关系报告可以保留中间版本页而不创建作品条目。
- **以 `ON DELETE SET NULL` 清除派生结果的外部目标**：目标不在作品目录中不代表关系消失；删除某个目录条目时，仍有用途的外部原作／父版本编号必须保留。
- **给外部编号另建完整作品表**：当前只需编号、语言、关系和来源链接；复制完整元数据会重建同样的存储和留存问题。
- **同时保存 favorite 布尔值与 Favorites 成员**：增加同步方向和不一致状态；用一份成员关系兼容旧 API。
- **Work 删除时静默清除个人资料**：合集、评分、备注、标签与收听记录表达用户意图；先明确清除这些资料，再允许单条或批量删除。
- **仅保留存续作品直接解析读到的报告**：可能移除其他保留报告的依赖，使被自述压住的声明生效并形成有效父链环；必须同时保持剩余证据的结构合法性。
- **客户端整份覆盖顺序或引入分数索引**：旧列表可能覆盖并发增删；增量移动配合现有 SQLite 写事务已能满足首版需求，整数位置也不需要精度与压缩机制。
- **收听会话流水与统计（audiobookshelf 的 `playbackSessions`）**：需要噪声闸口、跨午夜归属与清理任务，这些成本只服务于尚不存在的统计需求。
- **服务端复刻曲目推导**：格式标记与噪声词的启发式要在 Go 与前端两处同步维护，一旦分叉，key 与序号会互相矛盾。
- **按时长百分比表示进度**：媒体事实未测出前时长未知，百分比会错；序号在推导结果中总是可得。
- **保存整个播放队列（kikoeru 的 `state.queue`）**：文件被转换或改名后快照立即过时。
- **关系型闭包表或递归路径字典**：增加了查询复杂度与数据库存储负担；平铺相对路径加前缀索引在千级/万级规模下效率最高且实现最简洁。

## 后果

- Library Scan 有两项明确限制：未变目录内的原地改写不会被发现，需 Full Rescan（或完整成员刷新）；客户端属性缓存窗口内、尚未反映在目录属性中的变化可能推迟到后续扫描。非叶目录的名字或类型变化本轮即可核对发现，同名 rename 覆盖仍可能推迟；缓存过期后新 mtime 与库存不符，就会重新观察。
- 目录时间戳机制依赖文件系统：NTFS 与本次实测的本地／NAS Btrfs、Linux tmpfs、SMB 支持相应目录 mtime 语义；不更新目录 mtime 的 FAT／exFAT 等文件系统不能依赖普通重扫确认变化，必须使用 Full Rescan。10 秒边距不能补偿失去 NTP 同步的任意时钟偏差。
- 上述探针数据来自同一简化调度器、32 个并发目录的不变库探针，只比较沿用策略；[生产验收](../issues/library-rescan-measurement.md)中，普通重扫相较完整重扫将冷 HDD 遍历从约 44.70 秒降至 7.86 秒、读盘量从约 440 MiB 降至 139 MiB，SMB 热缓存流水线从约 17.31 秒降至 5.19 秒。冷机械盘需清缓存、SMB 需区分服务器缓存，完整重扫仍按全量读取计价。

- 物理目录被移除或改名且未通过正规流程修复前，作品副本会转入未绑定状态，但用户个人数据安全保留。
- 既有单作品 HTTP 删除接口已统一保护副本与个人资料，API 拒绝原因和后端测试保持同步。手动清理网页仍只按类别选择及展示汇总，不新增单作品删除、逐条候选或逐条阻止原因页面。作品删除不删除独立报告，不加载证据或重算其他作品；只清自身归属记录，并在提交后通知目录存在性变化。
- 关系占位详情及 `created_placeholders` 等未发布接口语义已移除；本轮通过重建开发库启用新结构，不保留未发布旧契约的兼容层。运行期删除作品不能级联清空独立报告。
- 详细分页协议、筛选接口与作品数据结构见 [works.md](../api/works.md)、[collections.md](../api/collections.md) 与 [libraries.md](../api/libraries.md)。
