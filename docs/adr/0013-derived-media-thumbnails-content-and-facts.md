# 0013 派生媒体：缩略图、文件内容分发与后台媒体事实

## 背景

作品包含大量高清插画与长音频文件。浏览器直接加载数 MB 的原图会占用大量内存和带宽；扫描时同步测量音频时长与图片像素，会让扫描受慢盘往返拖累。此外，浏览器媒体标签（`<audio>`、`<img>`）对流式 Range 与跨域鉴权有着特殊诉求。

## 决定

1. **按需缩略图服务与可丢弃派生缓存**：
   - 服务端提供动态缩略图生成能力，缓存按高度档位、文件版本和引擎标识生成不可变 HTTP 响应。
   - 缩略图缓存存放于磁盘独立目录，属于可随时丢弃重建的派生数据，不入数据库；只读请求不占全局准入槽。
   - 相同尺寸并发请求共享单次计算（Singleflight），设置防解压炸弹像素上限，首个引擎采用纯 Go 实现以保证跨平台免 CGO 交叉编译。
2. **基于库存清单（Manifest）的只读文件分发**：
   - 内容接口直接基于已存数据库库存投影出副本的虚拟文件树，禁止在请求到来时现场遍历磁盘。
   - 客户端媒体标签（如音频播放器）原生加载字节流；仅文件内容路由在完全缺少 Authorization 头时接受查询参数 `access_token`（`<img>`、`<audio>` 带不了请求头），支持单区间 HTTP Range 请求实现拖动播放。
   - 物理文件始终留在磁盘原位，仅服务清单中经安全校验的白名单文件，拒绝路径越界与符号链接逃逸。
3. **扫描后异步可抢占媒体事实补测（Enrichment）**：
   - 库存扫描流水线仅抓取文件基础元数据（大小、mtime、类型），快速完成入库并释放准入。
   - 音频时长、有损音频码率与图片像素宽高由后台补测在扫描完成后写入，只填测到的字段，已知值不被清空。
   - 补测持有准入闸的可抢占后台槽：扫描、文件管理、维护和会话令它停下并等最后一次写回落地；它自己从不拒绝这些任务。分批写回限制被抢占时丢失的工作。
   - 事实提交后通过 SSE 通知客户端重新读取；每个订阅者合并待处理信号，连接时补发一次，不维护事件历史。

## 放弃的方案

- **扫描时同步解析所有媒体元数据**：每个文件多一次读取，在机械盘与网络共享上拖慢扫描，并延长准入占用。
- **预先为全库所有图片生成多档缩略图卷**：产生大量可能永远不被浏览的冷图，增加磁盘占用，还要维护与原图的同步。
- **将图片与音频原始二进制存入 SQLite Blob**：数据库体积随媒体膨胀，文件也不能再用系统工具直接管理。

## 后果

- 新导入作品的列表或详情页在初次打开的几秒内，可能暂时显示未知的时长或图片尺寸，后台补测提交后随通知刷新。
