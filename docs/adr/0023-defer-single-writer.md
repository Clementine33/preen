# 0023 暂不引入全局单写入口

Status: Draft — 2026-10-11

SQLite 同时只能有一个写事务，但这本身不足以证明应用需要再建立全局单写入口。本次测量时，运行时写入使用共享 SQL 连接池，业务准入限制部分任务重叠，数据库沿用 [ADR 0008](0008-database-self-cleanup-and-retention.md) 的 immediate 写事务、busy timeout 与重试策略。

[真实准入负载测量](../issues/sqlite-write-contention-measurement.md) 的 35 次运行没有 BUSY/LOCKED，样本充足路径的 BEGIN p99 均低于 9 ms。最长 BEGIN 耗时为 1.73 秒，但该路径样本不足以计算 p99。现有证据未显示全局写入串行化能解决实际故障或带来足以覆盖改造成本的收益。

因此保留现有连接池和局部同步机制，暂不引入统一单写连接或命令队列。额外的写入口需要处理读写池边界、重入和文件发布后的数据库收尾；在收益未验证时，不增加这些契约。单独的关停生命周期修复不依赖这一决定。

这不是永久否决。后续功能改变并发模式、数据规模或事务长度时，应按新的实际负载重新测量。真实准入负载出现进程内 BUSY，或同一路径单次运行至少 100 个 BEGIN 样本的 p99 达到 2.5 秒，均应重新评估；稀疏路径的最大等待接近阈值时先补充测量。外部连接导致的 BUSY 需要另行处理。

若将来证实需要统一串行化，优先评估私有单连接写池与独立只读池。命令 Worker、FIFO 和 group commit 具有额外语义与成本，本次没有验证其必要性或批量收益。
