# 缩略图服务：可丢弃的派生缓存与可替换的缩放引擎

## 1 背景与边界

作品详情页的胶片带与叠卡要为一组插画（常见数十到数百张、单张数 MB）同时显示缩略图。回环或局域网部署下，浏览器直接取原图、用 `createImageBitmap` 缩放可用，但它把每张原图的完整传输与解码推给客户端；云部署下带宽与客户端内存都不成立。这是技术债，不是能力边界。

决定：缩略图由服务端按需生成，经 HTTP 与可丢弃缓存复用；任何节点都不维护缩略图卷（扫描时预生成、持久化并需与媒体库同步的派生文件集）。

## 2 扫描时记录图片尺寸

扫描用 Go 标准库 `image.DecodeConfig` 只读文件头，记录图片宽高，随清单文件条目存储，与 `bitrate`、`format` 同级。前端在像素到达前即可排版：标本框贴合真实比例，胶片带等高、宽度随比例。尺寸是元数据，不是缩略图，不改变 §1 的决定。

## 3 请求路径分层

1. **不可变地址**：缩略图地址带版本参数 `v = hash(大小, mtime, 目标高度, 引擎版本)`，响应 `Cache-Control: public, max-age=31536000, immutable` 并带 `ETag`。文件或引擎变化只改变地址，旧地址从不失效。
2. **缓存命中**直接返回（§4）。
3. **合并**：同一地址的并发请求共享一次计算（singleflight）。
4. **准入**：同时计算数上限为 CPU 数，等待队列有界；队列满时返回 `503` 与 `Retry-After`；请求上下文取消即撤出排队或中止计算。缩略图是只读路径，不占 ADR 0002 的全局准入槽。
5. **引擎**：解码、缩放、编码（§5）。
6. **写入缓存**：先写临时文件再改名，读方不会读到半个文件。

服务端自保不依赖前端：第 3、4 层按「多客户端」设计，前端限流（§6）只减少无谓排队。

**安全**：源路径按成员目录的包含规则解析（与 ADR 0002 直接文件管理同一套：拒绝越界、符号链接穿越）。解码前用 §2 的宽高检查像素总数，超过上限（约 1 亿像素）不解码，前端显示排线占位，防解压炸弹。

## 4 缓存是可丢弃的派生物

缓存与卷的区别：缓存随时可整体删除，按需重建，不入数据库，无需与媒体库同步，也不需要清理任务追踪原图增删。

- 本地：数据目录下的 LRU 目录，有容量上限，按访问时间淘汰；运行中删除整个目录也安全。
- 云端：换成对象存储加 CDN，地址与第 1 层语义不变。

## 5 引擎端口

缩放引擎是消费方声明的端口（ADR 0009）：输入源文件读取器与目标高度，输出编码字节与内容类型。

- **首个实现：纯 Go**。`image/jpeg`、`image/png`、`golang.org/x/image/webp` 解码，`golang.org/x/image/draw` 缩放；输出 JPEG，带透明通道的源输出 PNG。进程内执行，不产生子进程，也不引入新工具链。
- **升级路径：wazero 加 Rust WASI 模块**（`jpeg-decoder` 以 1/2 至 1/8 缩尺解码 JPEG，`fast_image_resize` 用 wasm SIMD 缩放），编译为 `wasm32-wasip1` 后以 `go:embed` 嵌入，实例池化。只在剖析显示解码是瓶颈时切换，只替换本层。
- 已知上限：PNG 无法缩尺解码，每次都要完整解码，因此重复访问的负载要靠第 1、4 层吸收，而不是靠引擎提速。

## 6 前端职责

- 胶片带与标本框按 §2 的尺寸排版，不等像素到达。
- 同时在途约 4 个请求，可见项优先；离开视口即用 `AbortController` 中止，使服务端对应计算撤出（§3 第 4 层）。
- 收到 `503` 按 `Retry-After` 退避重试。
- 过渡：服务落地前，允许浏览器直接缩放原图（`createImageBitmap`）。服务落地后删除该分支，不保留为长期的第二条路径。

路由与参数的最终形状在实现时写入 [docs/api.md](../api.md)。

## 拒绝的替代方案

- **浏览器缩放原图作为长期方案**：云部署下每张原图都要完整传输并在客户端解码，带宽与内存不可接受；只保留为 §6 的过渡。
- **维护缩略图卷**：扫描时预生成并持久化，需要与原图增删、改名、离线副本保持一致，同步与清理成本长期存在；缓存（§4）拿到同样的复用而不承担同步。
- **ffmpeg 子进程逐张缩放**：虽复用已有依赖，但每张图创建一次进程，高并发下进程数与 CPU 都会失控。
- **cgo 链接 libvips**：最快，但破坏 Windows 交叉构建（`task build:go:windows-x64`）。
- **libvips 编译为 WASM 在 wazero 中运行**：`wasm-vips` 面向 Emscripten 与浏览器，依赖 glib 与线程，WASI 下不可行；要走 WASM 路线，用 §5 的 Rust 模块。
- **JPEG 内嵌缩略图**：插画多为 PNG，且内嵌缩略图不可依赖。
- **只靠前端限流保护服务端**：云端有多个客户端，单个客户端的礼貌无法约束总负载。
