# 0003 短路由与不透明目录身份

## 背景

早期的界面与 API 将媒体库内的相对文件路径直接拼在 URL 路由中。这导致深层目录的 URL 过长、容易在各类代理与客户端中因特殊字符转义失效，且在分享链接中直接暴露了服务器底层的物理目录名称与结构。

## 决定

1. **确定性不透明身份（`dir_id`）**：由后端根据版本前缀、媒体库 ID、规范化库根路径指纹及库存中的准确相对路径，确定性计算出固定长度的不透明身份字符串。
2. **地址不包含文件名称**：前端导航与目录树读取仅使用短标识符 `dir_id`。实际的文件重命名、移动等业务请求，仍在请求体中传递相对路径，将路由标识与操作路径解耦。
3. **确定性与无状态映射**：
   - 同一媒体库根下的同一相对路径，重扫或重启后派生出相同的 `dir_id`，保证链接稳定。
   - 目录被改名或移动后，旧 `dir_id` 自动失效；若该路径重新出现，自然恢复原标识。
4. **纯寻址标识而非安全凭据**：`dir_id` 仅用于定位库存节点，不承载访问令牌或权限签名。后端在解析 `dir_id` 后，仍需执行包含性、越界防御与符号链接安全检查；任何歧义或未识别的标识均明确拒绝。`dir_id` 也可以出现在请求体里作为选择标识（如建批次的 `selection`），但仍然不是访问凭据。

## 放弃的方案

- **数据库持久化映射表**：为每个目录建立自增或随机 UUID 映射表，不仅增加了库表存储与索引开销，且在扫描重建、备份迁移时容易产生映射错位。
- **全路径 Base64 编码**：它是可逆的，不构成「地址不含名称」，长度也随路径增长。
- **随扫描重建的 folder UUID**：重扫后身份改变，链接随之失效。
- **用成员序号缩短地址**：记录被替换后同一序号指向另一个文件夹，旧链接会静默打开另一个对象；成员 id 的长度换来的正是「记录已替换」可被识别。

## 后果

- 物理目录改名或换根会导致对应的旧 `dir_id` 链接失效，客户端需要通过重新索引获取新链接。
